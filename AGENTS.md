# Project-local maintenance rules

- Changes that affect the same-account connection retry must preserve the fixed `CT-CONNECT-RETRY-001` v1.0 contract in `docs/local-patches/same-account-connect-retry.md`.
- Before handing off such a change, run `scripts/verify-cockpit-connect-retry.sh` in GitHub Actions; after an upstream merge, also perform the duplicate-retry review described in the patch specification.
- The local API service uses Rust Native. Its setup-only port is specified in `docs/local-patches/native-connect-retry.md`; also run `scripts/verify-native-connect-retry.sh` in GitHub Actions when updating its transport or the patched reqwest/hyper-util dependencies. Keep the Go reference contract intact.
- Preserve the Native Credits policy and Auto Reset contracts in `docs/local-patches/`. Reuse upstream protocol, continuation and quota-reserve implementations; do not reintroduce a second plaintext marker policy or silently bypass Credits when switching engines or credential identities.
- Build and run compilation-dependent checks in GitHub Actions on standard hosted runners for this public repository. Do not compile on this Mac, use paid/larger runners, or introduce paid build services. Use `npm run build:app` / `npm run build:app:cloud`, or the workflow UI; `build:app:local` is a compatibility alias that dispatches the same cloud workflow.
- Personal builds select only `macos-x86_64`, matching this Intel Mac. Keep every existing platform supported: Cloud Build accepts one platform or `all`; formal `v*` releases retain the signed multi-platform release workflow. Fork users can choose their own platform. Keep the Rust Native engine, matching Go sidecar, and existing application features.
- Reuse cloud caches by platform/architecture and dependency inputs. Run the frontend typecheck once per Cloud Build. Give intermediate artifacts short retention and replace rolling platform downloads instead of accumulating duplicate builds. Never cache or upload local account profiles, configuration, tokens, logs, signing keys, or other private data.
- The retry verifier defaults to native-only checks on the cloud runner. Use `--cross-platform` only for a change that needs that additional verification. Preserve the runtime contract and duplicate-retry review; selecting a personal Mac build does not require a full release matrix.
- After downloading and verifying the cloud-built App, remove obsolete project build caches, dependencies, dedicated toolchains, old clean source copies, and duplicate artifacts. Keep necessary source, Git history/remotes, runtime account/configuration data, and the current App. Do not create a full backup or require local build caches/toolchains to be retained. Do not remove shared toolchains or unrelated work without establishing that they belong only to this project.
- Keep `origin` pointed at the user's public fork and `upstream` at the canonical project. Merge upstream changes into the public branch without replacing source wholesale or discarding patch history. Follow `docs/cloud-builds.md` for cloud validation, downloads, cleanup, and public-fork synchronization; its current policy supersedes historical local-build/cache-preservation instructions in patch verification records.
